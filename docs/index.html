A blockchain, forged from scratch in Java.

BlockSmith is a working cryptocurrency built to understand how Bitcoin and Ethereum work under the hood: Proof-of-Work mining, ECDSA wallets, a gossiping P2P network, a REST API with a live dashboard, a small script VM that runs hashlock, timelock and multisig contracts, and an embedded database that lets a node survive a crash.

Try it

Mine a block, right here.

This runs the same Proof-of-Work loop as Block.mineBlock(): keep bumping the nonce until the SHA-256 hash starts with enough zeros. Each extra zero makes it about 16× harder. Once a block is mined, change its data and watch the hash stop being valid. That is why nobody can quietly rewrite a block.

Difficulty 4 is where the real node starts (it then retargets every 10 blocks). Your browser can try about 100,000 hashes per second, so it usually takes under a second. Difficulty 5 needs about a million tries.

The dashboard

Every node ships with a command deck.

Start a node and open localhost:7070. It is plain HTML, CSS and JavaScript on top of the REST API, with no build step. You can watch the chain grow, create wallets, send coins, mine, and deploy and claim contracts.

Press Ctrl/⌘+K and type: mine, send, deploy. Arrow keys and Enter do the rest.

Live activity feed

Contracts in two clicks

What's inside

Four layers, each built by hand.

The only dependencies are Gson for JSON, Javalin for HTTP, H2 as an embedded database, and JUnit for tests. Hashing and signatures use the JDK's built-in cryptography (MessageDigest, Signature).

Core chain

Sprints 0–6, 16–18

The data structures and rules that make a ledger tamper-evident.

  • SHA-256 block hashes with Proof-of-Work mining
  • Merkle root over each block's transactions
  • ECDSA (secp256r1) wallets with 0x… addresses
  • Signed transactions, mempool, 50 BSC mining reward
  • Balance checks that count pending spends, so you cannot double-spend
  • Embedded H2 database: on restart every stored block is re-validated, never trusted
  • Self-adjusting difficulty: retargets every 10 blocks toward one block per 10 s, with timestamp rules against fake times
  • Every block's contents are checked: no minted coins, no overspending, at most 16 KB and 50 transactions
  • Transaction fees: miners fill blocks by fee per byte and collect the fees

P2P network

Sprints 8–11

Nodes talk JSON over raw TCP sockets and agree on one chain.

  • HELLO handshake, PING/PONG heartbeat, dead-peer eviction
  • Peer discovery and seed-node bootstrap
  • Block and transaction gossip that skips the peer it came from
  • Orphan buffer for blocks that arrive before their parent
  • Chain and mempool sync for nodes that fall behind

API & dashboard

Sprints 12–13

A REST surface over the node, plus the web UI shown above.

  • Javalin server: blocks, transactions, mining, wallets, peers
  • Every write is broadcast to the network
  • One JSON error format for 400, 404 and 500
  • The dashboard is served from the same port as the API

Contracts & multisig

Sprints 14–15

A Bitcoin-Script-style stack machine that decides who can spend locked coins.

  • Opcodes: SHA256, EQUAL, CHECKLOCKTIME, CHECKSIG, CHECKMULTISIG, …
  • The VM never throws: a malformed script simply evaluates to false
  • Every node rebuilds the contract registry from the blocks themselves
  • M-of-N multisig with a signed hash of each claim, so signatures cannot be replayed
Architecture

One process per node.

BlockSmithNode starts the P2P server and the HTTP API together. The blockchain is the single source of truth, and everything else reads from it or writes to it.

Under the hood

Small code, big ideas.

Every class has THEORY comments that explain the idea behind the code. Here are two of the core pieces.

core/Block.javaProof-of-Work
public long mineBlock(int difficulty) {
    String target = "0".repeat(difficulty);

    // Keep incrementing nonce until we find a valid hash
    while (!hash.startsWith(target)) {
        nonce++;
        hash = calculateHash();
    }
    ...
}

public String calculateHash() {
    String dataToHash = index + timestamp
            + merkleRoot + previousHash + nonce;
    return HashUtil.applySha256(dataToHash);
}
contract/ScriptVMa hashlock
# locking script, stored on chain
SHA256 PUSH 41ec81d2…04fa EQUAL

# unlocking script, sent by the claimer
PUSH cafe42

# the VM runs unlock, then lock:
#   push "cafe42" → hash it → push expected
#   → compare → true = coins released

Anyone who knows the secret can claim the coins. Swap in CHECKMULTISIG and you need M of N signatures instead. In BlockSmith, a multisig wallet is just a contract with a different lock.

Run it

Three commands to a running node.

You need Java 20+ and Maven 3.9+.

Start a node with the dashboard

Then open http://localhost:7070/. The chain is saved under data/ and survives restarts.

$ git clone https://github.com/bartoszclapinski/BlockSmith $ cd BlockSmith $ mvn exec:java

Run the tests and the console demo

The demo mines blocks, compares difficulties, moves coins and shows tamper detection in the terminal. Custom ports: -Dexec.args="<p2p> <api>".

$ mvn test # 342 tests $ mvn exec:java \ -Dexec.mainClass=com.blocksmith.BlockSmithDemo
